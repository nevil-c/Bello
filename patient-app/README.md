# Patient call UI

Run with the local backend using the instructions in ../hospital-dashboard/TRANSCRIPT_SETUP.md. The launcher no longer asks for a speech-provider key. CALL records microphone audio, then displays Processing your recording until the backend returns the completed original-language transcript. No live partial text is generated. Accessibility supports keyboard entry, colour themes and larger text. Typed requests save directly without STT.

Rate my service collects a 1–5 rating, Yes/Partly/No resolution answer and an optional comment, linked to the saved request. The backend prevents duplicate feedback. The survey is patient initiated after help; there is no department completion signal. The home screen retains feedback for the most recent saved request in this app session only. Demo mode is offline and sends no requests.

Cancel stops capture or polling; an already uploaded recording can continue processing and remain visible in the clerk dashboard. No automatic retry is made. Closing the launcher stops its backend; interrupted jobs can be explicitly retried from retained recordings. The administrative sample dashboard remains separate; backend analytics require explicit --database selection in that server.

## Local streaming trial
Install requirements.txt and run `python prepare_stream_model.py` once in the same environment as the app. The default live engine is multilingual faster-whisper, using three-second incremental snapshots and one backend model. Vosk is an optional English streaming experiment: install `vosk>=0.3.44,<0.4`, run prepare_stream_model.py, and set BELLO_LIVE_ENGINE=vosk to enable it. Only then is its model loaded at startup. Microphone PCM frames (100 ms each) enter a bounded queue; a dedicated decoder emits changed partial text without re-transcribing growing recordings. No audio leaves the laptop/Pi. The one-second ding plays during capture. Faster-whisper still processes the complete recording for the saved clerk transcript. Partial words can change and may differ from final text. Other live languages require an appropriate Vosk model set with BELLO_STREAM_MODEL; final Whisper recognition remains multilingual. Keep BELLO_LIVE_ENGINE unset (or set to whisper) to use the default three-second partial approach. Pi 4 latency must be measured on the actual device.

Microphone endpointing uses WebRTC voice-activity detection on 20 ms frames, rather than a fixed loudness threshold. Recording ends after approximately two seconds without detected speech, or prompts for an empty request after ten seconds with no detected speech. All microphone audio is retained for Whisper; the detector only decides when to stop. Background speech can still extend recording. This detector does not load another transcription model.

Noise suppression is enabled by default: conservative spectral attenuation, low-frequency hum reduction, and a soft speech gate with 300 ms trailing protection. Both live snapshots and final WAV uploads use the cleaned audio. Speech endpointing uses WebRTC mode 3 and a minimum input RMS of 220 PCM units. Set BELLO_MIN_SPEECH_RMS lower for a quiet patient or higher to reject distant voices; this is a level threshold, not a reliable distance or speaker classifier. Set BELLO_NOISE_SUPPRESSION=0 to compare raw audio. Competing conversations can still be recognized; a close or directional microphone helps. One Whisper model remains loaded.

Stronger suppression tuning: default minimum speech RMS is now 450, with a relative 30% floor based on recently accepted speech level. Two voiced blocks out of three are required to start or reset the pause timer, reducing resets from isolated sounds. The noise gate attenuates non-speech more strongly, and spectral attenuation is increased. Lower BELLO_MIN_SPEECH_RMS if a quiet patient is missed. The background countdown animates at about 30 frames/second on the UI clock and eases back when speech resumes; microphone updates only start/reset it.
